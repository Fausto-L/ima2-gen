# 002 셸/내비게이션 — 좌측 레일 + 점진적 복잡도

서치 결론 중 가장 강한 패턴: 2026년 스튜디오 셸은 좌측 얇은 레일 +
작업별 중앙 워크스페이스이고, 사용자는 "결과물로 진입 → 피드에서 반복 →
캔버스/노드로 승격"하는 점진적 복잡도 동선을 따른다 (Runway/Leonardo/
Freepik/Kling 공통).

## 현재 문제

- 모드 전환이 `UIModeSwitch`(classic/node) + Agent 진입 + 설정 버튼으로
  흩어져 있고, 위계가 평평하다. "지금 어디에 있고 다음에 어디로 가는가"가
  화면 구조에서 읽히지 않는다.
- 첫 화면이 곧바로 컴포저다. 빈 상태가 안내 역할을 하지 못한다(003에서 처리).
- 갤러리는 모달이라 "작업 공간"이 아니라 "팝업"이다(004에서 처리).

## 작업 항목

1. **좌측 레일 도입**: `Sidebar.tsx` 상단에 아이콘 레일 추가 —
   홈(003) / 생성(현 classic) / 캔버스(canvas-mode) / 노드 / 자산(004) /
   에이전트 / 설정. 현 `UIModeSwitch`는 레일로 흡수.
   레일은 아이콘+툴팁, 확장 없음(수평 공간 절약 — 서치 패턴 #1).
2. **모드별 URL 해시 라우팅**: `#home` `#create` `#canvas` `#node` `#assets`
   `#agent`. 새로고침·뒤로가기에서 모드 복원. `persistenceRegistry.ts`에
   마지막 모드 저장.
3. **승격 동선**: 각 워크스페이스에서 다음 단계로 넘기는 액션을 상시 노출 —
   피드 결과 → "캔버스에서 편집" / "노드로 보내기", 노드 그래프 →
   "템플릿으로 저장"(006). 승격은 항상 현재 컨텍스트(이미지/프롬프트/설정)를
   갖고 이동한다.
4. **모바일**: 레일은 하단 탭바로 접힘(`MobileAppBar` 확장). 노드/캔버스는
   모바일에서 조회 전용 유지 — 서치 패턴 #17(desktop canvas, mobile
   companion) 그대로.

## 검증

- 모든 기존 진입점(설정, 에이전트, 카드뉴스 dev)이 레일 경유로 도달 가능.
- 해시 라우팅 새로고침 복원 계약 테스트 추가.
- 모바일 뷰포트(390px)에서 탭바 전환 스크린샷 확인.
