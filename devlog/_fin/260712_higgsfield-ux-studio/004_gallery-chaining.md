# 004 갤러리 체이닝 + 히스토리/자산 분리

서치 패턴 #7·#8: 스튜디오급 제품은 "방금 생긴 것"(피드/히스토리)과
"다시 쓸 것"(라이브러리)을 분리하고, 모든 결과물 타일을 다음 작업의
발사대(launchpad)로 만든다. 구현 비용 대비 체감이 가장 큰 P0.

## 4-1. 호버 체이닝 액션

`GalleryImageTile` / `HistoryStrip` 타일 호버 오버레이에 원클릭 체이닝:

- **영상으로** — 이미지를 I2V 프레임 소스로 넣고 비디오 모드로 이동.
- **편집** — canvas-mode로 이동, 현재 이미지 로드.
- **참조로** — 컴포저 참조 이미지 슬롯에 추가.
- **다시 굽기** — XMP 복원 경로 재사용, 프롬프트+설정 복원 후 컴포저 포커스.
- 기존 즐겨찾기/다운로드/메타데이터는 유지.

모바일은 hover 대신 탭 → 액션 시트(`MobileComposeSheet` 패턴 재사용).
기존 `ResultActions`가 이미 절반을 갖고 있으므로 액션 정의를 공용 모듈로
빼서 타일/뷰어/모달이 공유한다.

## 4-2. Assets 워크스페이스 (히스토리와 분리)

새 `#assets` 모드. 갤러리 모달을 대체하는 게 아니라 위계를 나눈다:

- **히스토리**(현행 유지): 세션 기준 시간순. "방금 무슨 일이 있었나".
- **Assets**(신규): 큐레이션 공간. 폴더 + 태그 + 검색 + 즐겨찾기.
  이미지/비디오/참조 자산(005)/프리셋(003)이 한 곳에.
- 히스토리 → Assets 승격은 명시적 액션("보관"). 자동 승격 없음 —
  실험 부스러기가 라이브러리를 오염시키지 않게(서치 패턴 #7의 근거).

서버: `/api/history`는 불변, 신규 `/api/assets` 라우트(폴더/태그 CRUD +
검색). 저장은 기존 스토리지 계층에 메타데이터 인덱스(JSON/SQLite) 추가.

## 4-3. 성능 선행 작업

타일 수가 커지므로 갤러리/피드 가상화(virtualization)를 이 단계에서 먼저
깐다. 비디오 썸네일은 hover 시에만 로드/재생, IntersectionObserver 게이트.

## 검증

- 체이닝 각 액션의 컨텍스트 이동 계약 테스트(이미지→I2V, 이미지→편집).
- 1,000타일 갤러리 스크롤 프로파일(가상화 전/후 비교 수치 기록).
- Assets CRUD + 검색 node:test 계약.
