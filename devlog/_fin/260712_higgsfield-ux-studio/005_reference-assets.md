# 005 영속 참조 자산 — @멘션 요소

힉스필드 Soul ID, Kling Element Library, Runway References가 공유하는 개념:
캐릭터/제품/스타일을 **이름 붙은 영속 자산**으로 만들어 세션을 넘어 재사용.
ima2는 참조 이미지가 생성 1회용이라 일관성 워크플로가 매번 수동이다.

LoRA 학습은 non-goal. 멀티 레퍼런스 주입(이미 모든 프로바이더가 지원하는
경로)만으로 시작한다 — Kling Element가 정확히 이 모델이고, 로컬 도구에는
이쪽이 맞다.

## 데이터 모델

```
element = {
  id, name, kind,            // character | product | style | scene
  refs: [imagePath...],      // 다각도 참조 1~6장
  notes?,                    // 프롬프트에 항상 붙는 서술(외모/재질 고정 문구)
  defaultStrength?,          // 프로바이더가 지원하면 매핑
}
```

저장: Assets 계층(004)에 `kind: element`로 통합. 갤러리 이미지에서
"요소로 저장" 체이닝 액션(004 오버레이에 추가)으로 생성 가능.

## @멘션 컴포저

- `PromptComposer`에서 `@` 입력 → 요소 자동완성 드롭다운(썸네일 포함).
- 멘션 확정 시 프리셋과 같은 **pill(칩)**로 표시. 생성 시점에 요소의
  refs가 참조 이미지 슬롯에 주입되고 notes가 프롬프트에 컴파일된다
  (003 컴파일러와 같은 파이프라인).
- 노드 모드: 요소를 노드로 드래그 인(참조 노드 타입 신설, 006과 연동).
- 비디오: I2V 참조 경로에 동일 주입.

## UX 디테일

- 요소 상세 페이지에 "테스트 시트" 버튼: 요소를 고정하고 4장 변형 생성 →
  일관성 눈검수용(서치에서 확인한 identity drift 비교의 경량판).
- XMP에 요소 id 기록(008 리니지에서 "이 캐릭터로 만든 것 전부" 필터 가능).

## 검증

- 멘션 파싱/주입 단위 테스트(다중 요소 + 프리셋 조합 포함).
- 참조 슬롯 상한 초과 시 우선순위 규칙 계약 테스트.
- 실제 캐릭터 요소 1개로 GPT/Gemini/Grok 3사 일관성 수동 검수 1회.
