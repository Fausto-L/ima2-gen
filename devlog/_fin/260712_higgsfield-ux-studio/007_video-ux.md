# 007 비디오 UX — 모션 프리셋 연동, extend, 프레임 체이닝

ima2 비디오는 기능 기반이 탄탄하다(first/mid/last 프레임 복사, 1080p,
white-canvas I2V shim). 이 문서는 새 모델 기능이 아니라 **기존 기능을
힉스필드식 어휘로 노출**하는 UX 작업이다.

## 7-1. 카메라 모션 칩 (003 연동)

`VideoControlsPanel` 상단에 카메라 모션 프리셋 칩 행. 선택 시 003 컴파일러가
프로바이더별 프롬프트 조각으로 변환. 힉스필드처럼 동시 선택 상한(2~3개)과
충돌 규칙(dolly in + dolly out 동시 금지 같은 배타 그룹)을 칩 UI에서 강제.

## 7-2. Extend (클립 연장)

완성 비디오의 마지막 프레임을 추출해 다음 I2V 생성의 첫 프레임으로 넣는
"이어가기" 액션. 프레임 추출 경로(first/mid/last 복사)가 이미 있으므로
연결 작업에 가깝다. 결과는 리니지(008)에 부모-자식으로 기록.

- 갤러리 비디오 타일 호버(004)에도 "이어가기" 노출.
- 이어붙인 클립 시퀀스는 순서 스트립으로 보여주고 ffmpeg concat으로 단일
  mp4 내보내기(로컬 도구의 강점 — 서버에 ffmpeg 의존성 추가 여부는 구현
  시점에 optional peer로 결정).

## 7-3. 비디오 결과 검수 UX

- 결과 카드에서 스크럽 가능한 호버 프리뷰(전체 재생 전 훑기).
- 프레임 단위 정지 → "이 프레임을 이미지로 저장" → 004 체이닝으로 연결.
- 변형 비교: 같은 프롬프트의 비디오 2~4개를 나란히 동기 재생하는 컴페어 뷰
  (병렬 생성 큐가 이미 변형을 만들어내므로 검수만 병목).

## Non-goals

- 타임라인 NLE, 오디오 트랙 편집. 립싱크/TTS는 프로바이더가 네이티브로
  지원할 때 재검토(`_future/` 후보).

## 검증

- extend 프레임 추출→주입 계약 테스트.
- 모션 칩 배타 그룹 규칙 단위 테스트.
- concat 내보내기 수동 검수 1회(코덱/해상도 혼합 케이스 포함).
