# 008 리니지 트리 + 비용 표시 승격

서치에서 확인된 시장 공백: Higgsfield/Runway/Krea/Leonardo 어디에도 1급
리니지(어떤 결과물이 어떤 부모·프롬프트·참조에서 나왔는지의 브랜치 트리)가
없다. ima2는 XMP 임베딩과 메타데이터 복원을 이미 갖고 있어 이 공백을 로컬
도구가 선점할 수 있다.

## 8-1. 리니지 기록

- 모든 생성물 XMP에 `parentId`(소스 이미지/비디오), `presetIds`(003),
  `elementIds`(005) 추가. 체이닝 액션(004)·extend(007)가 자동으로 부모를
  기록하므로 UI 추가 입력은 없다.
- 서버 인덱스: Assets 메타데이터 인덱스(004)에 lineage 간선 저장.

## 8-2. 리니지 뷰

- 결과 뷰어/메타데이터 모달(`ResultMetadataModal`)에 "계보" 탭: 부모 체인 +
  자식 분기 트리. 노드 클릭 = 해당 결과로 점프.
- 필터 연동: "이 요소로 만든 것 전부", "이 프리셋을 쓴 것 전부"(005·003의
  id 기록이 있으므로 인덱스 쿼리로 끝난다).
- 트리 시각화는 노드 캔버스 렌더러를 재사용하지 않고 단순 세로 트리로
  시작(읽기 전용, 오버엔지니어링 방지).

## 8-3. 비용 표시 승격

서치 패턴 #14(비용은 실행 지점에): 현 `CostEstimate`는 우측 패널에 있다.
이를 **Generate 버튼 자체**에 병기(버튼 라벨 아래 mono 소자로 "~$0.12 ·
4장"). 모델/품질/장수 변경 시 즉시 갱신. 우측 패널 상세는 유지.
프리셋·요소가 장수를 바꾸는 경우(변형 분기 등)도 반영.

## 검증

- lineage 간선 기록 계약 테스트(체이닝 3종 + extend).
- XMP 라운드트립에 신규 필드 포함 확인(기존 metadata-restore 테스트 확장).
- 버튼 비용 표기 갱신 계약 테스트(모델/장수 변경 매트릭스).
